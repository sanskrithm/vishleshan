### graph.rs (322 lines)
**Semantic graph IR with Karaka-labeled edges**

**Key Structures:**
```rust
pub struct SemanticGraph {
    nodes: Vec<Node>,
    edges: Vec<(NodeId, NodeId, Karaka)>,
    entry: NodeId,
    exit: NodeId,
}

pub struct Node {
    operation: Operation,
    inherited_context: HashMap<String, String>,  // Anuvrtti
}

pub enum Karaka {
    Source,      // Apādāna
    Instrument,  // Karaṇa
    Object,      // Karma
    Scope,       // Adhikarana
}
```

**Key Methods:**
- `propagate_context()` — Anuvrtti engine
- `topological_order()` — Execution planning
- `validate()` — Consistency checking

### lexer.rs (175 lines)
**ASCII-only hand-written FSM lexer**

**Token Types:**
```rust
pub enum Token {
    Morpheme { root, karaka },      // e.g., "sales-at"
    Verb { dhatu, sutra },          // e.g., "chid-tva"
    Eof,
}
```

**Features:**
- No regex (deterministic FSM)
- ASCII-only (universal compatibility)
- Zero-copy parsing where possible
- Comprehensive error messages

### semantic.rs (250 lines)
**3-phase semantic analyzer**

**Pipeline:**
```
Phase 1: Extract source (-at suffix)
    ↓
Phase 2: Accumulate instruments (-ena suffixes)
    ↓
Phase 3: Process operations (-tva/-ti suffixes)
    ↓
Output: SemanticGraph with Karaka edges + Anuvrtti context
```

**Key Feature: Anuvrtti**
- Once declared with `-ena`, parameters automatically inherited
- Recursive DAG propagation
- No re-declaration needed

## Compilation Pipeline (v0.2)

```
Input: "sales-at revenue-ena chid-tva yuj-tva drsh-ti"
  ↓
[Lexer] Tokenize (lexer.rs)
  Tokens: [Morpheme("sales", "at"), Morpheme("revenue", "ena"), ...]
  ↓
[Semantic Analyzer] 3-Phase Parse (semantic.rs)
  Phase 1: Extract source
  Phase 2: Accumulate parameters
  Phase 3: Process operations
  ↓
[Graph Builder] Create nodes + edges
  Nodes: [Source, Filter, Sum, Render]
  Edges: Karaka-labeled [Source, Instrument, Scope]
  ↓
[Anuvrtti Engine] Context Propagation (graph.rs)
  Propagate "revenue" through all operations
  ↓
[Validation] Graph Consistency Check (graph.rs)
  Verify entry/exit requirements
  ↓
[Topological Sort] Execution Planning (graph.rs)
  Order: [Source → Filter → Sum → Render]
  ↓
Output: Execution-ready semantic graph
```

## Paninian Principles Implemented (6/12)

✅ **Karaka Theory** (src/graph.rs lines 17-44)
- Apādāna (-at): Source relation
- Karaṇa (-ena): Instrument/parameter
- Karma (-asya): Output target (reserved)
- Adhikarana (implicit): Scope inheritance

✅ **Anuvrtti** (src/graph.rs line 270+)
- Once declared, parameters inherit automatically
- Recursive DAG traversal for propagation
- No re-declaration needed

✅ **Sutra System** (src/dhatu.rs line 99+)
- -tva: Lazy continuation (pipeline)
- -ti: Terminal execution (collect)

✅ **Dhatu System** (src/dhatu.rs line 50+)
- 15+ categorized operations
- ASCII parsing for each
- Extensible for custom operations

✅ **Adhikara** (src/semantic.rs line 80+)
- Entry node holds source
- Exit node receives output
- Scope propagates through DAG

✅ **Semantic Graph IR** (src/graph.rs line 210+)
- Nodes: Operations or data
- Edges: Karaka-labeled semantic dependencies
- DAG structure: Optimizer-ready
