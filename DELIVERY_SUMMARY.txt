================================================================================
                            LANGUAGE SPECIFICATION
================================================================================

KĀRAKA SUFFIXES (Grammatical Cases)
─────────────────────────────────────────────────────────────────────────────
  -āt   : Apādāna (Source)     - First morpheme, identifies dataset
  -ena  : Karaṇa (Instrument)  - Inheritable parameter (Anuvṛtti)

SŪTRA SUFFIXES (Control Flow)
─────────────────────────────────────────────────────────────────────────────
  -tvā  : Continuation          - Lazy operation (deferred)
  -ti   : Completion            - Terminal operation (required at end)

DHĀTU ROOTS (Semantic Operations)
─────────────────────────────────────────────────────────────────────────────
  chid  : Cut/Filter            - Predicate filtering
  ci    : Gather/Group          - Group-by aggregation
  yuj   : Join/Aggregate        - Numerical summation
  dṛś   : See/Render            - Pipeline execution

ANUVṚTTI (State Inheritance)
─────────────────────────────────────────────────────────────────────────────
  Once -ena binds a parameter, it's inherited by all subsequent operations
  without re-declaration. This implements the Sanskrit principle of Anuvṛtti.

================================================================================
                            COMPILER PIPELINE
================================================================================

FOUR-STAGE COMPILATION

  INPUT: Sanskrit morpheme string
    ↓
  STAGE 1: LEXER (token.rs + lexer.rs)
    └─ Tokenize morpheme stream
    └─ Output: [Token...]
    ↓
  STAGE 2: PARSER (parser.rs)
    ├─ Phase 1: Extract source (-āt)
    ├─ Phase 2: Extract instruments (-ena)
    ├─ Phase 3: Extract operations (dhātu forms)
    └─ Output: Program { source, instruments, operations }
    ↓
  STAGE 3: SEMANTIC ANALYZER (compiler.rs)
    ├─ Establish context (Anuvṛtti)
    ├─ Lower operations to query steps
    └─ Output: QueryPlan { context, steps }
    ↓
  STAGE 4: RUNTIME EXECUTION
    ├─ Polars LazyFrame materialization
    ├─ Pipeline fusion and execution
    └─ Output rendering

Each stage has strongly-typed input/output, making the compiler robust.
